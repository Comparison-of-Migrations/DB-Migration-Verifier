적용 버전: v0.1.0-preview.2 · 2026-10-15

이 설명서는 앱을 처음 실행해 두 DB를 비교하고 결과를 보관하는 순서입니다.
DB별 실제 확인 범위는 `한국어 README <../README.ko.rst>`_ 에 있습니다.

1. 내려받고 실행하기
--------------------

`공개 릴리스 <https://github.com/Comparison-of-Migrations/DB-Migration-Verifier/releases/tag/v0.1.0-preview.2>`_
에서 OS에 맞는 ZIP을 받습니다.

* macOS Apple Silicon: ``DB-Migration-Verifier-macos-arm64.zip`` 을 새 폴더에 풀고
  ``DB-Migration-Verifier.app`` 을 엽니다.
* Windows x64: ``DB-Migration-Verifier-win-x64.zip`` 을 새 폴더에 풀고
  폴더 안의 ``Verifier.Desktop.exe`` 를 엽니다. 함께 있는 파일을 유지합니다.
* .NET 런타임이 포함되어 SDK 설치나 앱 계정 생성이 필요하지 않습니다.
* 현재 묶음은 미서명·미공증 Preview입니다. OS에서 실행을 막는 경우 그 알림을 확인하세요.
  정식 서명된 배포물은 아직 제공하지 않습니다.

오른쪽 위 언어 버튼으로 한국어와 영어를 전환할 수 있습니다.

2. 첫 화면에서 고르기
---------------------

* **새 검사 시작:** 실제 두 DB에 연결해 비교합니다.
* **검사 결과 파일로 보기:** 앱에서 저장한 JSON 결과를 엽니다. 새 비교는 실행하지 않습니다.
* **예시 결과 보기:** DB 없이 화면을 둘러봅니다. 실제 DB 검사 증거로 사용하지 않습니다.
* **저장한 검사 이력:** 이 기기에서 저장하거나 연 JSON 결과의 기록을 봅니다.

3. 원본·대상 DB 연결하기
------------------------

1. 같은 DBMS의 서로 다른 원본·대상을 준비합니다.
2. 실제로 양쪽 DB의 쓰기를 정지한 뒤 화면의 쓰기 정지 확인을 선택합니다.
3. 양쪽의 서버 주소, 포트, DB 이름, 조회 계정과 비밀번호를 입력합니다.
4. 필요하면 고급 연결 설정에서 인증서 경로를 지정합니다.
5. **두 연결 확인**을 누르고 양쪽 확인 결과와 오류 안내를 읽습니다.

.. list-table:: 일반적인 기본 포트 — 실제 서버 설정을 우선합니다
   :header-rows: 1

   * - DBMS
     - 포트
   * - PostgreSQL
     - 5432
   * - SQL Server
     - 1433
   * - MySQL / MariaDB
     - 3306

PostgreSQL·MySQL·MariaDB의 인증서 입력은 서버 인증에 사용할 CA 경로입니다.
SQL Server의 입력은 **서버 공개 인증서의 정확한 일치값**이며 CA 인증서와 구분합니다.
SQL Server에서 경로를 비우면 OS의 인증서 신뢰를 사용합니다.
잘못됐거나 만료된 인증서, 서버 이름 불일치는 접속 정보와 인증서를 수정한 뒤 다시 확인합니다.

접속 정보를 바꾸거나 저장한 설정을 불러오면 양쪽 연결을 다시 확인합니다.
같은 실제 DB를 원본과 대상으로 지정한 경우에는 서로 다른 DB로 수정합니다.

접속 설정을 이 기기에 보관하기
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

양쪽 연결 확인 후 **접속 설정 저장**을 사용할 수 있습니다.
기본으로 서버·포트·DB·계정·인증서 경로만 저장합니다.
**비밀번호도 OS 보안 저장소에 저장**을 선택하면 비밀번호는 OS 보안 저장소에 보관합니다.
불러온 뒤에는 쓰기 정지와 양쪽 연결을 다시 확인하세요.

**저장한 접속 삭제**는 저장한 설정과 해당 OS 비밀번호 항목을 삭제합니다.
현재 화면의 입력은 직접 지우거나 앱을 닫을 때까지 메모리에 남습니다.

4. 사전 확인과 검사 범위 선택
-----------------------------

사전 확인에서 읽을 수 있는 범위와 제한을 확인합니다. 제한이 있는 항목은
그 이유를 유지하며, 확인하지 못한 범위를 일치로 간주하지 않습니다.

검사 선택 화면에서는 검사 분류와 테이블 범위, 제공되는 DB 범위를 고릅니다.
테이블을 검색하고 원본·대상 테이블 및 컬럼 대응을 확인합니다.
자동 대응이 맞지 않으면 화면에서 제공하는 대응 기능으로 수정합니다.

**실행 전 확인**에서 선택한 검사, 테이블·컬럼 대응, 제한과 시험 범위를 검토합니다.
범위를 고쳤다면 변경된 요약을 확인한 뒤 실행합니다.

5. 선택적인 별도 DB 동작 시험
-----------------------------

일반 비교는 원본·대상을 읽기만 합니다. 동작 시험을 선택할 때는 원본·대상과
분리된 시험 DB를 준비하고, 시험 테이블·입력·기대 결과와 필요한 부모 자료를 확인합니다.
준비 내용을 검토하고 확정한 뒤 실행 범위로 돌아갑니다.

엔진·구조에 따라 자동으로 준비할 수 없는 제약이나 추가 입력이 있을 수 있습니다.
확정할 수 없는 경우에는 그 시험을 미실행으로 남기고 이유를 확인합니다.
확정한 동작 시험은 별도 시험 DB에 쓰기를 수행합니다.

6. 실행하고 결과 읽기
---------------------

실행 화면에서 처리 단계와 진행 위치를 확인합니다. 중단을 요청하면 처리하지 못한 범위는
미검증으로 남을 수 있습니다. 끝난 결과에서 다음을 구분해 읽습니다.

* **불일치·위반:** 확인한 값·정의·구조 등이 다르거나 무결성 위반을 발견했습니다.
* **확인 불가·미검증:** 권한·관측 제한·지원 범위·중단 등으로 판단을 끝내지 못했습니다.
* **일치:** 해당 검사에서 관측한 범위가 같습니다.

같은 검사에 알려진 차이와 미검증이 함께 있으면 두 집계에 모두 나타날 수 있습니다.
막대와 항목 수는 검사 항목의 집계이며, 행 수나 전체 DB 성공률이 아닙니다.
분류나 항목을 눌러 검사 ID·대상·판정 근거·제한 이유를 확인합니다.

7. 저장하고 다시 열기
---------------------

결과 저장에서 형식을 선택하고 파일 위치를 지정합니다.

* **JSON:** 검사 ID·판정·발견 사항을 보관하고 앱에서 다시 열 때 사용합니다.
* **CSV:** 표 형태로 열람하거나 공유할 때 사용합니다.
* **HTML:** 브라우저로 결과를 열람하거나 공유할 때 사용합니다.

여러 형식을 선택하면 각 저장 대화상자를 완료합니다. 일부 저장을 취소하거나 실패했다면
화면에 안내된 완료 형식을 확인합니다. 공유 전에는 DB·객체 이름 등 식별 정보를 확인하세요.

홈의 **검사 결과 파일로 보기**에서 JSON을 열고 원래 검사 ID와 판정을 확인합니다.
파일을 여는 동작은 저장된 결과를 복원하며 현재 DB를 다시 검사하지 않습니다.

이력 화면의 **결과 열기**로도 파일을 열 수 있습니다. 파일을 옮기거나 변경·손상한 경우
기록에서 열리지 않을 수 있습니다. 원래 정상 파일을 직접 선택하세요.
**기록만 삭제**는 이력 항목을 지우며 원래 결과 파일은 유지합니다.

8. 문제가 생겼을 때
-------------------

.. list-table:: 먼저 확인할 사항
   :header-rows: 1
   :widths: 30 70

   * - 증상
     - 확인 방법
   * - 연결이 미확인으로 남음
     - 필수 입력과 실제 쓰기 정지 상태를 확인한 뒤 두 연결을 다시 확인합니다.
   * - 접속·인증서 오류
     - 서버·포트·DB·계정·비밀번호와 인증서 종류·경로·유효기간·서버 이름을 확인합니다.
   * - 관측 제한이 표시됨
     - 해당 검사 상세의 이유와 조회 권한, 지원 범위를 확인합니다.
   * - 시험 준비를 확정할 수 없음
     - 별도 DB 분리, 입력·기대 결과, 제약과 부모 자료를 확인하거나 시험을 미실행으로 둡니다.
   * - 결과 파일을 열 수 없음
     - 앱이 저장한 정상 JSON인지, 파일이 이동·변경·손상되지 않았는지 확인합니다.

`문제 제보 <https://github.com/Comparison-of-Migrations/DB-Migration-Verifier/issues/new/choose>`_
에는 앱 버전·OS/아키텍처·DB 종류/버전, 재현 절차와 비식별 오류를 적습니다.
실제 비밀번호·키·고객 데이터·운영 덤프는 첨부하지 마세요.

현재 Preview의 범위
-------------------

정식 서명·공증과 native Windows x64 장비 인수, 실제 EKM 및 전체 운영/규모 인수는 남아 있습니다.
화면의 제한과 미검증 이유를 결과와 함께 보관하세요.
구체적인 확인 이력과 라이선스는 `한국어 README <../README.ko.rst>`_ 를 참고하세요.
