# 요구사항과 인수 기준

사용자 확정 범위는 [RULE](../RULE.md), 접속·검사 방식은 [설계](product-design.md)가 정본이다. 아래는 전체 제품의 인수 기준이다. 기술 기본값은 사용자 확정 정책과 구분한다. 2026-10-02 첫 실행판의 부분 구현·실제 증거는 [NATIVE-01](native-implementation.md)에 구분한다. 아래 전체 범위의 인수를 모두 통과했다는 뜻은 아니다.

| ID | 출처·결과 | 통과·실패 확인과 증거 |
|---|---|---|
| DMV-01 | 사용자: 원본·대상 무변경 | 비교 전후 데이터·정의·권한 변경 없음. 각 DBMS 실제 검사 |
| DMV-02 | 사용자: 엄격 상세 비교 | 같은 건수·합계에서 값만 다른 반례 탐지. 공백·NULL·수치·중복·키 없음 포함 |
| DMV-03 | 사용자: 권한 자동 안내 | 불완전 조회 범위를 숨기거나 누락 객체로 단정하지 않음 |
| DMV-04 | 사용자: 검사 선택 | 선택·실행·결과에 동일 범위가 연결되고 제외 이유가 남음 |
| DMV-05 | 사용자: 별도 시험 공간 | 원본·대상에 쓰기 시험이 실행되지 않음. 기대 결과·실행 범위 기록 |
| DMV-06 | 사용자: 방해 표시 | 취소·시간 초과·연결 실패 시 완료·중단·미시작 구분. 전체 통과 금지 |
| DMV-07 | 사용자: 로컬 보관 | 파일 다시 열기·CSV·HTML에서 동일 범위·판정 복원. 손상·공간 부족 처리 |
| DMV-08 | 사용자: 값 비노출 | 실제 값·민감 키·비밀값이 화면·로그·보고서·Git에 없음 |
| DMV-09 | 사용자: 큰 DB·다중 플랫폼 | 분할 처리·UI 응답·취소를 실제 데이터 규모와 OS·DBMS별로 검증. 무한 크기 보장 금지 |
| DMV-10 | 사용자: 연구 반영 증거 | 연구 연결표의 각 제품 사례를 실제 구현·검증 증거로 연결 |

원문 전체는 기존 과제 RULE에 보관돼 있다. 앱의 실제 사용자 DB 처리와 공개 제출 예시 자료를 구분한다. 동료 감상·사용자 판단을 AI가 대신 만들어 완료시키지 않는다.

## 작성 형식

상세 조건은 ID → 출처·목표 → 사전 상태·사건 → 단일 관찰 결과(EARS) → Given/When/Then 인수 기준 → 반례 → 증거 → 상태로 작성한다. 근거 없는 성능 수치와 승인되지 않은 정책을 필수 조건으로 추가하지 않는다.

## 검증기 분석과 요구사항의 연결

[연구 연결의 RP 대응표](research-to-product.md)의 세부 분석을 아래 요구사항 명세에 사용한다. RP는 연구→제품 연결 ID이며 과제 통과 기준이나 구현 완료 번호가 아니다. DBMS별 기술 조건은 [검사 설계](product-design.md), 반례·증거는 아래 상세 기준에 연결한다.

| 요구사항 | 분석 근거 |
|---|---|
| DMV-01·DMV-05·DMV-11 | RP-B01·RP-S01과 원 구현의 clone/직접 조회/시험 정리 경계 |
| DMV-02 | RP-D01·RP-C01·RP-C02와 19과제 전체 값/관계 비교·과제 전용 변환의 구분 |
| DMV-03 | RP-A01·RP-A02·RP-S01: 권한 정의·실제 역할 동작·관측 실패의 구분 |
| DMV-04·DMV-06 | RP-S01: 선택 범위·판정·실행 상태와 미검증 이유 |
| DMV-07·DMV-08·DMV-09 | 전체 메모리 수집·원값 기록 등 그대로 이식할 수 없는 구현에 대한 분석 |
| DMV-10·BRB-C01·BRB-C03·BRB-C04 | RP-D01부터 RP-S01까지의 검사·판정·화면·실제 확인 증거 연결 |

원 논문의 PASS/FAIL 라벨 재현과 앱의 범용 비교 정확성은 다른 검증이다. 정의 차이는 숨기지 않되 업무 결함·원본 결함의 판정에는 별도 근거가 필요하다. 자료형·키·제약·객체·권한별 세부 지원과 성능은 앱 구현 후 실제 증거로 확인한다.

## 상세 인수 기준

2026-10-01 검사 명세 초안. ID는 기존 DMV 요구의 하위 번호이며 과제 BRB 번호와 구분한다. 각 행은 출처인 상위 DMV 요구·설계 항목, 사건에 대한 단일 요구(EARS), Given/When/Then, 실패를 드러낼 반례와 증거를 연결한다. 모든 행의 상태는 **미구현·미검증**이다. 합성 자료만 사용하고 실제 값이 담긴 실행 로그를 증거로 제출하지 않는다.

### 연결·권한·무변경 — DMV-01·DMV-03·DMV-08

| ID | 단일 요구 | Given / When / Then과 반례 | 필요한 증거 |
|---|---|---|---|
| DMV-01.1 | 기본 비교 중 원본·대상에 변경 명령을 보내지 않아야 한다 | 합성 DB 두 개 / 모든 읽기 분류 실행 / 업무 행·정의·권한 불변. 반례: view·routine·sequence 또는 사용자 변환을 통해 직접/간접 변경 실행 | DBMS별 명령 추적과 선택 범위 전후 대조 |
| DMV-01.2 | 비교용 snapshot을 확보하지 못하면 관측 제한을 명시해야 한다 | snapshot 불가 엔진 / 비교 / 쓰기 정지 조건·한계 표시. 반례: 앱이 DB 옵션 변경, NOLOCK 사용, 서로 같은 시점 보장 주장 | 설정 불변 확인·결과 관측 방식 |
| DMV-01.3 | 관측 중 DB나 정의 변경이 확인되면 영향 범위를 판정 불가로 표시해야 한다 | 실행 중 정의 변경/접속 전환 / 탐지 / 관련 완료 확정 차단. 반례: 재접속 후 이어서 전체 일치 | 변경·전환 주입 결과 |
| DMV-03.1 | 잘못된 접속 입력 시 수정 가능한 오류를 표시해야 한다 | 틀린 주소·포트·암호·DB 이름 / 연결 / 해당 오류 안내, 화면 유지. 반례: 앱 종료·비밀값 포함 예외 표시 | 입력별 KR/EN 결과·비노출 확인 |
| DMV-03.2 | 인증서 검증 실패 시 자동으로 보안 설정을 낮추지 않아야 한다 | 신뢰 불가/이름 불일치 인증서 / 연결 / 실패. 반례: 암호화 해제 또는 TrustServerCertificate 자동 전환 | DBMS별 TLS 양성·음성 연결 기록 |
| DMV-03.3 | 목록 가시성이 불완전하면 누락 객체를 확정하지 않아야 한다 | 보이지 않는 테이블/정의 / 사전 확인·비교 / 미검증 이유. 반례: 빈 catalog를 객체 없음으로 처리 | 제한 계정/전체 조회 계정 대조 |
| DMV-03.4 | 필터·마스킹된 관측을 전체 값 일치로 표시하지 않아야 한다 | 차이가 숨겨진 RLS 행/마스킹 컬럼 / 비교 / 전체 값 판정 불가. 반례: 양쪽 가려진 값만 같아 일치 | PG row_security·SQL RLS/UNMASK 반례 |

| DMV-03.6 | 미지원 타입·버전·객체를 발견 목록에서 숨기지 않아야 한다 | 특수 타입/정의 조회 불가 객체 / 사전 확인 / 종류·한계 표시. 반례: 지원 안 됨을 적용 대상 아님으로 처리 | 지원 registry와 발견 목록 대조 |

### 화면 완료의 필수 조건 — DMV-12

2026-10-01 사용자 확정. 정책은 [RULE의 UI-01–UI-04](../RULE.md), 버튼과 선택 요소의 목록은 [제품 설계](product-design.md)를 따른다. 아래 네 항목의 macOS UI 교정 증거는 [UI-ALIGN-01](../evidence/ui-alignment/README.md)에 있다. Windows 실제 UI·배율/모니터·첫 방문 사용 평가와 미구현 기능은 남으므로 전체 인수 완료는 아니다. HTML 시안 점검과 actual native 증거는 [현재 상태](status.md)에서 구분한다. 특정 화면의 구현 완료 보고에는 모든 작동 버튼·선택 요소의 실제 증거가 필요하다. DBMS 카드·checkbox·대응 대상은 키보드 조작, 일부 선택, 충돌 비활성 이유, 검색/일괄 선택의 범위 보존도 확인한다.

| ID·출처 | 단일 요구 | Given / When / Then과 반례 | 필요한 증거 |
|---|---|---|---|
| DMV-12.1 · UI-01 | 버튼의 중요도를 크기·배치·강조로 구분해야 한다 | 주요/보조/취소가 있는 화면 / 표시·창 크기·언어 변경 / 주요 행동이 구분되고 모두 누를 수 있음. 반례: 모든 버튼 동일 강조·작은 보조 버튼으로 접근 곤란 | 버튼 목록의 중요도 근거·KR/EN 화면과 클릭 영역 확인 |

**2026-10-02 증거 연결:** DMV-12.1은 9페이지·3크기·KR/EN 위계/조작 영역 캡처, DMV-12.3은 버튼·키/입력 보존·차단·파일/검사 결과, DMV-12.4는 실제 실행 전환 관찰과 동작 줄이기 대체를 [매트릭스](../evidence/ui-alignment/README.md)에 기록했다. 녹화/프레임 시간 측정이나 Windows 관찰을 수행한 것으로 세지 않는다.
