# UI-ALIGN-01 · 웹 시안과 Avalonia 화면 일치 작업

2026-10-02 사용자 지적: 실제 앱 UI가 웹에서 구현한 시안과 크게 다르다. **상태: 완료 · macOS 화면 교정 및 제한 상태 확인.** NATIVE-01의 기능 실행 완료를 화면 일치 완료로 취급하지 않는다. 이 문서는 이번 교정 작업의 순서·진행·재개 기록이고, 영구 화면 구성은 [제품 설계](product-design.md), 값은 [토큰](../.ui-craft/tokens.md), 인수 기준은 [요구사항](requirements.md)이 정본이다.

## 작업 종료 기록

2026-10-02 R0–R11의 macOS 교정·실제 흐름과 제한 화면을 확인하고 R12에서 임시 재개 제약을 제거했다. 작업 중에는 압축 때마다 AGENTS·본 문서·status·RULE·brief·tokens를 실제로 다시 읽고 최신 실행 앱과 대조했다. 이제 이번 작업만을 위한 강제 재개 조건은 종료됐다. RULE UI-01–UI-04와 상시 문서 진입 규칙은 유지한다. Windows 실제 UI, 두 OS 배율/모니터와 첫 방문 동료 평가는 전체 제품 인수에 남는다.

## 교정 기준과 수정 전 차이

디자인 기준은 최신 `examples/ui-prototype/index.html`이다. HTML 시안의 예시 결과·가짜 연결 상태를 실제 앱에 옮겨 통과로 표시하지 않는다. 운영체제 title bar·파일 dialog는 네이티브로 유지하며, 그 외 앱 본문의 배치·위계·여백·입력/선택·상태·동작을 기준에 맞춘다. WebView로 HTML을 감싸는 방법은 쓰지 않고 C#·Avalonia 네이티브로 구현한다.

작업 시작 때 웹 연결과 네이티브 결과를 직접 관찰하고 다른 페이지는 소스를 대조했다. 아래는 그 시점의 수정 전 차이다. 최종 상태는 진행표와 증거 기록을 따른다. 수정 전 증거는 [웹 연결](../evidence/ui-alignment/baseline-web-connect.png), [네이티브 결과](../evidence/ui-alignment/baseline-native-results.png), 기준 소스 해시는 [기준 기록](../evidence/ui-alignment/baseline.json)에 있다. 두 캡처는 서로 다른 페이지·배율이므로 같은 화면의 픽셀 차이 증거가 아니다. 각 페이지 교정 때 일치 조건으로 다시 찍는다.

| 현재 구현 | 기준 시안으로 바꿀 것 | 이유 |
|---|---|---|
| 색만 옮기고 대부분 StackPanel·기본 컨트롤로 나열 | 공통 shell·Grid 열·전용 입력/선택/상태·표 템플릿 | 화면의 밀도·정렬·조작 영역이 시안과 다름 |
| 단계 번호가 TextBlock, 완료/방문/미래 단계 구분 약함 | 번호 배지·완료 체크·현재 좌측 강조·방문 단계 버튼 | 현재 위치와 이동 가능 범위를 직관적으로 표시 |
| 기본 라디오·체크박스, 사전 확인이 단순 요약 카드 | DBMS 카드·분류 헤더·대상 표·중앙 정렬 상태 | 사용자가 지적한 선택기의 완성도와 표 구조 복원 |
| 결과 숫자 한 문장, 길게 나열한 상세 | 독립 지표·분류별 수치 행·필터·안전한 상세 목록 | 차이와 미검증을 한눈에 비교하고 필요할 때 상세 탐색 |
| 모든 행동에서 공통 opacity·페이지 전체 재생성 | 행동별 press/전환/펼침/상태 피드백, 초점·스크롤 보존 | 단순 색상·fade만으로 실제 동작 피드백을 대체하지 않음 |

**비교 방법:** 웹 CSS px와 Avalonia DIP를 같은 논리 창 크기로 맞춘다. macOS Retina 캡처의 물리 픽셀 2배를 글꼴/여백 2배 차이라고 판단하지 않는다. OS title bar를 제외한 앱 client 영역을 비교한다. 960×720, 1138×1088, 1440×900 논리 크기의 KR/EN과 내용 스크롤을 확인했다. 요청한 1138×1097은 이 macOS 화면에서 창 높이가 1088로 제한되어 1097 확인으로 기록하지 않는다. 정확한 값은 토큰을 따른다. 자동 픽셀 차이만으로 글꼴 렌더링 차이와 구조 누락을 함께 평가하지 않는다.

## 구현 단위와 순서

R0 공통 shell/테마 → R1 시작 → R2 연결 → R3 사전 확인 → R4 선택 → R5 선택 시험 준비의 표시 → R6 실행 전 → R7 진행 → R8 결과 → R9 저장 → R10 dialog/공통 오류 → R11 전체 흐름/회귀 → R12 완료 정리 순서다. 각 페이지의 상태와 버튼까지 확인하고 다음 페이지로 간다. 미구현 엔진 기능은 정직한 제한 상태로 화면을 갖추며, 실제 기능 구현은 별도 추적한다.

공통 shell·테마·버튼·상태 배지·폼 패널·분류 헤더·행·notice·dialog를 실제 반복에 맞춰 재사용한다. MainWindow의 연결/검사/파일 기능과 기존 보호된 PasswordTextBox를 보존하면서 화면 구성은 페이지별 View/템플릿으로 나눈다. 새 추상 프레임워크를 만들지 않는다. 선택·입력·언어·결과·스크롤·초점은 단순 렌더링 때문에 유실되지 않도록 한다.

### R0 · 모든 페이지의 공통 골격

- 기준: HTML `topAndRail`, `render`, `footer`. 현재: `MainWindow.Render`와 `App.axaml`.
- 수정: shield 로고·앱명·모드/언어, 60h 헤더·220w 단계 rail·본문·84h 고정 footer. rail 하단 안내를 아래에 고정한다. 단계 배지·완료 체크·현재 줄 좌측 강조와 방문 가능 버튼을 구현한다. 실제 모드 표시는 ‘읽기 전용/합성 예시’로 구분하고 HTML의 ‘실제 DB 연결 없음’ 문구를 실제 검사에 적용하지 않는다.
- 본문 제목/부제/섹션 간격과 최대 폭, 36/44 시작 제목·28/36 페이지 제목·14/22 본문을 토큰화한다. 아이콘은 동일한 stroke 규칙의 벡터로 구현하고 텍스트 glyph/이모지로 대체하지 않는다. 주요 48h·보조 44h, 첫 행동 52h를 유지한다.
- 행동: N01 방문 단계·뒤로, N03 언어. 처리 중 미래 단계 이동 차단. 입력 변경 시 접속 확인 무효화. 언어 전환은 상태를 유지하고 동작 줄이기 설정도 유지한다.
- 동작: press 80ms/색 120ms, 페이지 200ms. 진행 카운터·타이핑마다 페이지 fade를 재생하지 않는다. 이동 후 제목/첫 유효 입력으로 초점, 뒤로/펼침은 기존 초점·스크롤 보존.
- 확인: 같은 크기의 웹/네이티브 시작·연결·결과 캡처, 고정 footer와 rail, KR/EN 줄바꿈, 최소 창에서 가림 없음, Tab/Enter/Space/뒤로. R0 확인 전 각 페이지 완료 처리 금지.

### R1 · S0 시작

- 기준: HTML `home`, 최신 `01-current-home.png`. 현재: `Home()`.
- 수정: 큰 제목·부제·도움 문장과 우측 예시 보고서 미리보기, 그 아래 균형 잡힌 단일 행동 줄(새 검사/파일 열기/예시), 바로 아래 파일 설명, 설명이 있는 세 행동 열, 논문 제목·연구 설명과 연구 반영 보기를 같은 순서·위치·크기로 배치한다. 우측 미리보기의 3/2/45는 HTML의 정적 합성 설명 수치이며 실제 엔진의 예시 실행·실제 DB 결과와 구분해 표시한다.
- 버튼: B01 최상 채움, B02 외곽선, B03 quiet, B04 연구 안내. 높이·기준선 일치, 문구 중앙·새 검사 화살표 우측 고정. 파일 열기는 새 검사나 DB 연결을 요구하지 않는다.
- 동작/상태: 시작 페이지 전환, file dialog·취소·형식 오류 notice, 예시 결과 전환/애니메이션, 연구 dialog. 이미 열린 실제 결과를 예시와 혼합하지 않는다.
- 확인: 1분 내 도움 대상/세 행동 파악 가능한 구성, 네이티브 정상·손상 JSON 열기, 예시 구분, 긴 영문 논문 제목/행동 줄 정렬. 첫 방문 동료 평가 자체는 별도 미검증으로 유지한다.

### R2 · S1 DB 연결

- 기준: HTML `connect`, `connectionSide`, `02-connect.png`. 현재: `Connections()`.
- 수정: 4종 DBMS 카드 행, 원본/대상 독립 패널·아이콘·상태 배지·구분선. 서버/포트는 한 줄의 넓고 좁은 입력, DB/계정/암호는 같은 폭. TLS/CA와 실제 지원 인증/제한을 고급 설정에서 펼친다. 미지원 MySQL/MariaDB 카드도 ‘준비 중’으로 보이며 선택·접속을 막는 이유를 안내한다. SQL Server는 메타데이터 구현/실제 서버 미검증을 그대로 표시한다.
- 버튼: B22 카드 label 전체+radio 방향키, B06 고급 연결 설정 헤더 전체, B05 두 연결 확인→관측 확인 후 S2. 기존 한 번의 접속·Inspect 경로는 유지하고 HTML의 가짜 두 단계 성공을 만들지 않는다.
- 동작/상태: 선택 indicator·테두리, 설정 펼침, 양쪽 연결 중/확인/실패. 변경 시 이전 확인 무효화, 포트 오류/동일 DB/TLS 실패는 해당 입력·패널 가까이 표시. 암호 비저장·접근성 마스킹을 보존한다.
- 확인: 기본 라디오 모양만 있는 상태를 카드 완료로 인정하지 않는다. Tab/방향키, 양쪽 오류, 인증서 입력, 연결 중 중복 실행 차단, 뒤로·언어 전환 입력 보존, 기존 엄격 TLS 테스트 회귀.

### R3 · S2 사전 확인

- 기준: HTML `capabilities`, `02-capabilities.png`. 현재: `Preflight()`·`SummaryRow()`.
- 수정: ‘검사 분류 / 원본·대상 / 검사 가능 범위 / 안내’ 4열 표, 상태 배지와 보조 이유를 분리. 아이콘·배지·권한 안내 버튼 상하 중앙 정렬. 불완전 가시성 notice와 별도 동작 시험 안내를 시안 위치로 옮긴다.
- 버튼: B08 필요한 권한 보기(실제 어댑터 관측과 필요한 권한만 설명), B09 검사 범위 선택. 관리자 권한 자동 부여·숨겨진 객체를 없음으로 처리하는 기능은 없다.
- 동작/상태: 범위 표 진입, 권한 dialog, 미조회·일부·불가의 이유 표시. 실제 미구현을 ‘가능’으로 꾸미지 않는다.
- 확인: 4열 정렬·KR/EN 긴 이유·현재 발견 개수·권한 부족·RLS·미지원 이유가 다음 요약과 결과까지 보존됨. 경고 아이콘 중앙 정렬 F01/F02 재확인.

### R4 · S3 검사 선택·대상 대응

- 기준: HTML `select`, `tableRows`, `matchingOptions`, `03-table-selection.png`, `03-matching.png`. 현재: `SelectChecks()`.
- 수정: 5개 분류 카드(독립 checkbox / 아이콘 / 제목·설명 / 가능 상태 / caret), 64h 헤더 전체 펼침. 세부 검사 ID·지원 이유는 펼침 안에 둔다. 테이블 검색·지우기·검색 결과 전체/일부 선택·해제, 선택/표시 개수, 원본/대상/대응 방식의 가상 목록 표를 만든다.
- 버튼: B10 전체 헤더 펼침, B23/B24/B26 검색 범위 조작, B11/B25 대응 drawer, B12 시험 준비, B14 실행 전 확인. checkbox를 헤더 버튼 안에 중첩하지 않고 형제로 구성한다.
- 의존: 검색/일괄 선택은 실제 chosenTables에 연결한다. 현재 엔진은 동일 이름만 허용하므로 수동 대응 UI는 지원 이유를 표시하며 실제 적용은 엔진의 일대일 매핑 구현 후에만 활성화한다. 이름 차이를 숨기거나 화면에서만 적용됐다고 표시하지 않는다.
- 동작/상태: header caret/본문 펼침·check/행·개수 전환, 빈 검색/빈 선택/일부 조회. 검색이 숨겨진 선택을 바꾸지 않고 일괄 조작은 검색 결과만 변경한다. 검색 입력마다 전체 페이지 재생성 금지.
- 확인: F03/F04, checkbox와 펼침 독립 Enter/Space, 부분 선택·숨은 선택 보존·빈 목록·선택 없음 차단, 긴 schema.table 가로 가림 없음. 대응 미구현 상태와 실제 지원을 구분한다.

### R5 · S3-T 별도 시험 준비·선택 상태

- 기준: HTML `trialPreparation`, `trial`, `03-trial-ready.png`. 현재: 준비 페이지 없음, Behavior checkbox 비활성.
- 수정: 선택 시험은 기본 해제하고 ‘준비 기능 미구현’ 이유를 해당 카드에 표시한다. 준비 화면의 별도 DB 패널·분리 안내·값/기대 결과 표·확인 영역을 디자인하되, 실제 생성/분리 검증/쓰기 경로가 없으면 실행은 비활성이다. 시안 모드에서만 합성 준비 상태를 탐색할 수 있고 실제 준비 완료와 혼동하지 않게 한다.
- 버튼: B12/B13, 준비 취소·복귀. 실제 지원 시 완료 DB의 안전한 정보는 준비 버튼 우측에 표시하고 입력 변경 시 무효화한다(F05). 호스트/접속 정보는 영구 보고서에 추가하지 않는다.
- 동작/상태: panel 전환·확인 결과·무효화 피드백, 분리 불명/미구현 이유. 준비 안 된 실제 DB를 준비됨으로 표시하지 않는다.
- 확인: UI의 비활성/설명 상태와 합성 예시를 확인한다. 이번 교정의 완료는 실제 쓰기 시험 구현 완료를 뜻하지 않는다. 기존 source/target에 새 쓰기 경로가 생기면 교정 범위 실패다.

## R11·R12 완료 조건

- 모든 페이지의 공통 shell·콘텐츠 구조·크기·정렬·상태·필수 행동이 웹 기준과 대조돼 있고 사유 없는 차이가 없다. 미구현 기능의 제한 화면은 검증하고 실제 구현과 혼동하지 않는다.
- UI-01–UI-04와 해당 B01–B26/N01–N03의 실제 상태·키보드·동작 애니메이션 증거가 있다. 미구현 기능 버튼은 왜 비활성인지 확인한다. 구현된 기능은 기본/처리/완료/오류/취소 등 해당 상태를 확인한다.
- macOS 실제 앱의 KR/EN·세 데스크톱 논리 창 크기, 두 DB 연결→비교→중단/결과→저장→홈 파일 재열기, 합성 예시와 제한 상태를 확인한다. Windows 교차 빌드도 확인하되 Windows 실제 런타임·모니터/배율·첫 방문 평가가 없으면 전체 DMV-12 인수 미완료를 유지한다. 이번 화면 교정 종료와 전체 제품 인수를 구분한다.
- 기존 정확한 비교·TLS·무쓰기·암호 접근성·안전한 결과 파일 테스트가 필요한 변경에 따라 회귀 확인됐다. CSS/HTML 예시 결과를 실제 테스트로 세지 않는다.
- 각 진행표 행에 실제 증거 또는 제한 근거와 제한 화면 확인이 연결되고, 계획/미검증을 완료로 고쳐 쓰지 않는다. R11 확인 뒤 R12에서 현재 기록을 정리하고 **AGENTS의 이번 임시 재개 절만 제거**한다.

## 최종 확인 / 다음 제품 작업

[증거 안내](../evidence/ui-alignment/README.md)와 [기계 판독 기록](../evidence/ui-alignment/review.json)에 페이지별 웹/native 캡처, 버튼·키·기능 결과, 소스/빌드 해시와 제한을 연결했다. 전 페이지(시험 안내 포함) × 세 크기 × KR/EN의 54개 native와 54개 웹 캡처는 같은 논리 크기로 비교했다. Retina 물리 픽셀 2배와 OS title bar 28 DIP는 앱 배치 차이로 세지 않았다.

실제 격리 PostgreSQL 17 TLS fixture의 8개 테이블과 양쪽 각 500만 행 합성 테이블에서 진행·resize·KR/EN·동작 줄이기·취소를 관찰했다. 중단 보고서 `c461d961-75d0-45c2-b71e-77419da603ff`를 실제 저장·검증했고 최신 빌드의 시작 화면에서 DB 연결 없이 재열기했다. 이전 100만 행 중단 보고서 `fd471d22-a9e6-4384-9b22-7cb323e54e37`도 보관했다. 두 보고서는 DATA/SCHEMA 시작한 검사와 ACCESS/OBJECT 미시작을 구분하고 이미 관측한 차이를 보존한다. 규모별 성능/최대 메모리 인수 시험은 아니다.

교정 중 암호 입력 스타일 키 누락, 라디오 방향키 재렌더 충돌, resize 후 진행 snapshot 유실, 형식 오류 JSON의 미처리 예외를 발견해 수정했다. 실제 암호 화면/접근성 마스킹과 TLS 연결을 다시 확인했다. 최신 언어·고급 설정의 실행 전환/초점 보존, 입력 보존, dialog Tab/Escape 복귀, 손상 파일 오류 → 정상 파일 복구도 확인했다. UI에서 timeout·강제 연결 끊김을 새로 주입한 것은 아니며 엔진 반례와 UI 취소 관찰을 구분한다.

공통/실제 PostgreSQL 회귀는 38개 통과·실패/건너뜀 0이다. 잠금 복원의 macOS arm64·Windows x64 publish가 성공했고 macOS 최신 앱을 실제 실행했다. 한 번의 macOS 병렬 publish MSBuild worker 종료 뒤 단일 worker 재시도는 성공했으며 원인을 추정하지 않는다. Windows 실제 런타임은 미검증이다. 일회용 fixture는 완료 정리에서 제거하고 사용자 DB는 사용하지 않았다. commit/push·배포하지 않았다.

**다음 제품 작업:** 미구현 세부 검사·DBMS·Windows 임시 ACL/자원 보호를 확장한다. 수동 대응, 실제 시험 DB, LiveCharts2, CSV/HTML·이력·선택 비밀 저장소는 별도 구현이다. 전체 DMV-12·첫 방문 1분 평가·BR-B 배포/사이트 연결을 완료로 기록하지 않는다.
