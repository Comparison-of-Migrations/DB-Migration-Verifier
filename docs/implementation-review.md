## 현재 행동

정본·코드의 미구현 지점을 대조했다. 먼저 I01의 판정/결과 불변식과 I02의 실제 내보내기 경로를 수정하고 의미 있는 반례·실제 앱으로 확인한다. 그 뒤 I03부터 이어간다. 원본/대상 변경·비밀값 노출·자동 성공/우월성 주장은 허용하지 않는다.

### I03 · 대응 구현 시작

- 원본→대상 테이블/컬럼 일대일 대응을 실제 엔진에 연결한다. 동일 이름은 기본, 수동 대응은 값 변환 승인이 아니다. 데이터는 대응 순서로 정확히 비교하고 이름/타입/위치/정의 차이는 구조에 남긴다.
- source scope와 target-only scope는 선택 식별을 구분한다. 한 원본을 다른 대상으로 대응한 뒤 남은 대상 테이블이 숨겨지면 안 된다. 자동 대응과 수동 대응의 충돌도 검증한다.
- 전체 컬럼 중 대응되지 않은 항목이 있으면 데이터 전체 일치 금지. 대상 선택 충돌·검색/선택 보존·취소/적용은 실제 dialog와 실행 전 요약에서 확인한다.
- 결과 형식 2에 실제 선택 대응만 안전한 이름으로 보존하고 형식 1의 기존 JSON은 계속 읽는다. 내보내기/재열기/화면을 모두 연결하기 전에는 I03 완료로 표시하지 않는다.
- 다음: Core 모델/엔진/codec/반례 → file/CSV/HTML → 실제 selector/요약/실행 → PostgreSQL/한영 native 증거. 임시 재개 제약은 계속 유지한다.

### I01·I02 수정·검증

- 발견: 테이블 선택을 생략하고 두 inventory가 비면 DATA-01이 Equal로 끝났다. 파일은 Equal+미확인 issue, 제외 검사의 완료/차이, 예시/어댑터 모순, 진행 중 상태와 중복 finding ID 등을 받아들일 수 있었다.
- 수정: 빈 범위·미확인 DB 식별 차단, 보수적인 전체 일치 집계, 결과 불변식과 필수 JSON 필드/중복 속성 확인. 실제 데이터가 있는 빈 테이블은 빈 inventory와 구분한다.
- I02: 안전한 같은 모델의 CSV·HTML 전체 내보내기와 쓰기/다시 읽기 무결성 확인 후 원자 교체를 구현 중이다. HTML escape/CSP·외부 요청 없음, CSV 전체 quoting/수식형 이름 보호. CSV 이름 보호는 읽기용이며 원래 이름은 JSON에 남는다. 모든 스프레드시트 버전의 재저장 안전을 보장하지 않는다. 근거: [OWASP CSV Injection](https://community.owasp.org/attacks/CSV_Injection), [.NET 필수 생성자 매개변수](https://learn.microsoft.com/en-us/dotnet/standard/serialization/system-text-json/required-properties).
- UI: 형식별 저장 위치 확인, 중간 취소/실패에서 완료 형식 표시, 재열기 처리중·오류 복구. 한영·선택/주요 버튼·동작 애니메이션은 그대로 적용한다.
- 검증: 실 disposable TLS PostgreSQL을 포함한 59개 시험 통과(실패/건너뜀 0). 마지막 UI 색/HTML 번역 변경 뒤 core 46개 재확인, macOS arm64·Windows x64 publish 성공. native KR/EN 960×720·1138×1088·1440×900 저장 화면, Space/동작 줄이기, 세 형식 실제 저장, 중간 취소의 JSON 보존, 잘못된 파일의 기존 화면 보존, DB 없는 JSON 재열기를 확인했다. 최종 한영 HTML을 브라우저로 읽고 CSV 전체 12 검사/판정/상태/finding을 JSON과 대조했다. [증거](../evidence/implementation-review/README.md)를 따른다. Windows 실행은 하지 않았다.
- 추가 발견/교정: PG catalog의 pg_% wildcard가 정상 pgfoo schema를 숨겼다. literal pg_ 접두사를 제외하도록 바꾸고 실제 차이 탐지 반례를 추가했다. 모호한 테이블/컬럼 식별은 임의 대상 선택 없이 차단한다.
- 한계: JSON 전체 payload/결과 모델 메모리와 Windows ACL은 I07, 실제 Windows/스프레드시트 재저장/디스크 full UI는 미확인이다. 영구 파일은 값/키/접속 정보를 포함하지 않는다. I03부터 전체 과정은 남아 있어 임시 재개 제약을 유지한다.

### I03 현재 검증 상태

Core·파일·CSV/HTML·native 선택/요약/결과 재열기 연결을 구현했다. 형식 2 대응을 저장하며 기존 형식 1 파일도 읽는다. 실제 PostgreSQL 이름/순서 변경 반례를 포함한 73개 시험 통과(실패/건너뜀 0), macOS publish 성공. 선택 대상 중 원본과 이름이 같은 미대응 대상도 별도 scope로 유지한다. 점을 가진 SQL 식별자는 segment를 인용해 충돌을 피한다. 첫 시험에서 record 안 list 참조를 비교한 assertion을 발견해 실제 항목 비교로 고쳤다.

아직 완료 아님: 실제 native selector의 취소/검색/중복 비활성/적용/컬럼 없음/한영/키보드/창 배치, 실행 전 요약→실제 비교→형식 2 저장/재열기를 확인해야 한다. 현재 macOS 앱은 새 실행판이며 실제 UI 검증을 이어간다. 일회용 TLS fixture는 `dmv-pg.5vhHss42`(시스템 temp)이고 credential은 그 안의 owner-only ui.json에서만 읽는다. 진행 자료/로그에 암호를 출력하지 않으며 끝에 자신의 container/image/temp만 정리한다. 이전 fixture `dmv-pg.PyJe7Bvv`는 정리했다.

### I03 native 인수 중 발견

실 TLS PostgreSQL `rename_source → rename_target`, `identifier → new_identifier`, `label → title`을 UI로 적용해 DATA-01 일치·SCHEMA-01 이름/컬럼 차이를 확인했다. 취소/Escape 초안 폐기·검색의 선택 유지·중복 대상 비활성 이유·형식 2 JSON/CSV/HTML 저장·DB 접속 없는 JSON 대응 재열기를 확인했다. 키보드에서 ListBox row에 초점만 있고 SelectedItem이 없거나 기본 이벤트가 먼저 처리되면 Enter가 활성화되지 않는 결함을 발견해 tunnel Enter/Space 경로·명시 초기 선택·선택 후 호출 버튼 초점 복귀를 교정 중이다. 영어 960×720에서 방향키→Enter로 미대응 선택과 복귀를 실제 확인했다. 수정판의 초기 Enter/Space·세 크기·한영 최종 증거가 남아 있어 I03 인수 중을 유지한다.

### I04 다음 구현 범위

PostgreSQL 17 공식 pg_constraint/pg_index/pg_partitioned_table 문서를 대조했다. 우선 테이블/컬럼 속성·PK/UNIQUE/FK/CHECK/배제 제약·인덱스/partition의 실제 catalog를 같은 snapshot에서 읽고 속성별로 비교한다. OID·DB별 물리 파일/통계 값은 이름/선언 속성으로 해석하거나 범위 밖으로 구분하며 원 SQL 정의는 메모리에만 둔다. 정의 비교를 실제 제약 위반/DATA-02·실행 동작 보장으로 표시하지 않는다. 미지원·부분 수집은 알려진 차이와 함께 판정 불가를 남긴다. 기존 합성/SQL Server adapter에 전체 완전성 플래그를 임의로 넣지 않는다. 원본/대상 쓰기는 계속 금지한다.

### I04 구현·엔진 확인 중

PostgreSQL 17의 같은 READ ONLY REPEATABLE READ snapshot에서 테이블/컬럼 선언, PK/UNIQUE/FK/CHECK/배제 제약, 인덱스 정의·상태·포함·조건·옵션, 다단 partition/상속 연결·경계를 수집하고 고정 속성별 kind로 비교하도록 연결했다. OID 대신 schema/이름/선언 signature를 사용하고 pg_catalog search_path를 고정했다. 정의와 literal·객체 이름은 메모리에서만 비교하고 영구 보고서는 테이블·컬럼·속성 종류·내부 번호만 보관한다. 권한 부족 query는 SAVEPOINT로 snapshot을 회복하며 해당 section을 판정 불가로 둔다. 이것은 업무 DB의 DDL/DML 변경이 아니다. 부분 수집에서 미관측 객체의 부재를 단정하지 않고 알려진 값 차이와 관측 제한을 병기한다. 중복 fact의 임의 첫 값 선택도 금지했다. 외부 테이블·constraint trigger는 부분 범위로 유지하고 partition/상속 부모의 데이터는 하위를 몰래 빠뜨려 전체 일치로 표시하지 않는다. 개별 하위 테이블은 목록에 포함한다.

실 일회용 TLS fixture에 속성 변형 자료를 준비했다. 컬럼·FK 동작/지연·CHECK 검증·배제·인덱스·하위 partition 등 실제 변형 30종과 동일 구조/외부 객체, core 속성별 차이·부분 가시성·중복·비노출/파일을 포함한 166개 시험 통과(실패/건너뜀 0). UI 사전 확인·세부 분류·실행 전 제한·한영 finding·HTML에도 실제 속성 결과를 연결했다. 새 finding의 최종 보고서 불변식과 실제 native UI/저장·기존 형식 재열기·두 RID publish는 확인 중이다. I04 전체 및 DATA-02 원본 결함 검사는 아직 완료가 아니다.

### I03·I04 인수 확인 및 다음 경계

I03의 초기 Enter/Space가 ListBox 선택·기본 처리 및 key-up 초점 이동 때문에 무반응/재열기를 만들었다. tunnel key-down에서 소비하고 key-up에서 선택 버튼을 실행하며 초기 선택과 호출 버튼 초점 복귀를 명시했다. 한국어·영어 960×720/1138×1088/1440×900에서 selector·충돌·취소·적용, 방향키/Enter/Space·동작 줄이기, 실제 PG 이름/컬럼 순서 변경→엄격 값 일치와 정의 차이→형식 2 세 파일/DB 없이 재열기를 확인했다. 선택 목록의 기본 보라색 띠도 프로젝트 스타일로 교정했다. 대규모 컬럼 목록·Windows 실제 UI는 후속 확인이다.

I04 최종: 새로운 TLS 일회용 DB를 처음부터 준비하는 전체 절차로 168 시험 통과(실패/건너뜀 0). 잘못된 검사 ID로 속성 차이를 이동한 보고서와 기록된 이름 변경을 구조 일치로 바꾼 보고서의 거부도 확인했다. macOS 실제 네 가지 사례(기본값·FK 삭제 동작·인덱스 키 순서·다단 partition 경계)를 세 구조 검사/안전한 위치로 표시했고, 12 검사·4 대응·4 finding이 JSON/CSV/HTML에 보존됐다. private expression/원 SQL/계정 값 비노출을 대조하고 HTML 브라우저 표시, DB 없는 형식 2 재열기와 기존 형식 1 재열기를 확인했다. 세 창 크기의 한영 상세를 확인했다. macOS arm64와 Windows x64 publish 성공은 Windows 실제 사용 증거가 아니다.

SCHEMA 검사는 수집한 선언·상태의 비교이며 실제 CHECK/FK 위반(DATA-02), 미래 입력·역할 로그인·운영 성공은 검증하지 않는다. 외부 테이블/constraint trigger 및 수집 실패는 이유를 유지한다. 실제 임시 fixture는 `dmv-pg.jQq0rwn8`로 새로 준비했으며 비밀번호는 owner-only 파일에서만 읽는다. 자신의 이전 fixture 정리와 새 fixture 수명은 작업 끝에 관리한다.

### I05 시작 · 권한과 의존 객체

선택 테이블에 연결된 owner/ACL/컬럼 권한·관련 역할과 멤버십·기본 ACL, RLS 정의, trigger/routine/view/sequence/사용자 타입을 catalog에서만 관측한다. 암호 verifier, 사용자 함수·view 실행·sequence 발급은 금지한다. OID를 이름/signature로 바꾸고 원 정의·계정명은 메모리에서만 비교한다. 정의 차이를 실제 인증/행 정책 실행 성공으로 표시하지 않는다.

먼저 선택 테이블의 관련 정의를 연결하고, 테이블에 연결되지 않은 DB 객체/관련 서버 설정까지 완전히 발견한 것으로 가장하지 않는다. 전역 객체 선택 모델과 가시성·세부 관측 실패를 검토하며 불완전 범위에는 미검증을 유지한다. 공식 PG17 pg_policy/pg_auth_members/pg_default_acl의 적용·권한·상속 옵션을 대조했다. 실제 변화/제한 계정/무변경과 영구 파일 비노출 시험까지 완료 전 I05 완료 금지.

사용자가 웹의 동작 재현이 미흡하다고 지적했다. I05 adapter 확장을 중간에 멈추고 빌드 불가 상태를 남기지 않도록 미연결 수집 호출을 제거했다. I05 속성 registry/범주별 Core 연결은 초안이며 실제 수집 완료가 아니다. 원본/대상 사용자 정의 table access method를 일반 heap 읽기로 오인하지 않도록 관측 경계를 좁혔다.

### 2026-10-02 · REPLICA-01 · 복제 기준과 재개 방법 교체

사용자가 웹을 원본으로 고정하고 bottom-up·한 컴포넌트·명세/검증/LOCK·압축 시 국소 복구 규칙을 확정했다. 웹을 native 동작에 맞춰 확장하던 W01 접근은 중단했다. 당시 파일과 실제 로드된 웹의 inline style/script가 달랐다. 미검증 파일 후보를 [제외 후보](replica/source-candidates/README.md)에 보존하고 로드된 코드로 원본 파일을 맞췄다. 규칙·지도·상태·컴포넌트 명세는 [docs/replica](replica/MASTER_RULES.md)가 정본이며 현재 진입점은 AGENTS다. 과거 교정 완료 기록을 새 LOCK 증거로 옮기지 않는다. I05 초안/Core registry는 보존했으나 실제 수집 완료가 아니다. 압축 시 기존 결정을 재설계하지 않고 활성 컴포넌트와 직접 부모/자식만 확인한다. 현재 상태의 세부 항목은 COMPONENT_STATUS에만 유지한다.
