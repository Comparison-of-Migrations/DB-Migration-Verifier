# NATIVE-01 · C#·Avalonia 첫 실행판

상태: **완료 · 첫 실행판**, 2026-10-02. 사용자가 요청한 다음 구현 묶음의 완료 기록이다. 제품 전체·BR-B 제출 완료와 구분한다. 전체 범위의 정본은 RULE·제품 설계·요구사항이다. 압축 뒤 AGENTS·본 문서·status를 다시 읽고 진행했으며, 아래 증거 확인 후 이번 임시 재개 제약을 제거했다. 상시 규칙은 유지한다.

## 이번 작업의 완료 조건

1. SDK·패키지를 고정하고 C# 공통 엔진·DB 접속 계층·Avalonia 데스크톱 앱·검증 프로젝트를 생성한다.
2. 논문 제목·도움 문장·세 행동을 가진 한국어/영어 시작 화면에서 검사 시작과 결과 파일 열기를 제공한다. 버튼의 중요도·키보드·실행 피드백·애니메이션을 확인한다.
3. 실제 읽기 전용 접속과 첫 비교 경로를 연결한다. 이번에 구현한 세부 항목만 판정하며 나머지는 이유와 함께 미검증으로 남긴다. 별도 시험 쓰기는 첫 실행판에서 실행하지 않는다.
4. 합성 DB에서 같은 건수의 값 차이·중복·조회 제한·중단을 검증하고 값·비밀 없는 결과 파일 저장/재열기를 확인한다. 실행하지 못한 OS·DBMS·자료형은 지원 확인으로 기록하지 않는다.
5. 실제 macOS 앱을 실행해 화면 증거를 남기고 README 실행 방법·현재 범위·남은 전체 제품 작업을 갱신한다.
6. 위 증거를 기록한 뒤 AGENTS의 NATIVE-01 임시 재개 제약을 제거한다.

## 구현한 것과 검증 증거

- .NET SDK 10.0.401 arm64를 공식 SHA-512 검증 뒤 로컬 캐시에 설치했다. 시스템 PATH는 변경하지 않았다. 기본 SDK 첫 실행이 개발용 HTTPS 인증서를 생성했으며 신뢰 처리하지 않았다. Avalonia 12.1.3, Npgsql 10.0.3, SqlClient 7.1.1 등 버전·lock 파일을 고정했다.
- Core/Data/Desktop/Tests를 분리했다. 임의 정밀 숫자·NULL·문자·중복을 엄격히 비교하는 행 다중집합 엔진을 연결했다. 행 순서만 무시한다. 같은 건수나 해시만으로 일치시키지 않는다. 선택 범위와 실행·판정·미검증 이유를 별도로 보관한다.
- PostgreSQL 17에서 엄격 TLS·읽기 전용 repeatable-read·row_security=off로 실제 비교했다. 사전 확인→분류/테이블 선택→실행 전 확인→진행/취소→결과/세부 위치→JSON 저장/재열기를 연결했다. MS SQL은 접속·TLS·일부 컬럼 메타데이터 코드만 있으며 실제 서버·값 검증 증거는 없다.
- macOS 실제 .app에서 논문 제목·도움 문장·세 행동이 있는 시작 화면, 한국어/영어, 키보드 입력과 Space 실행, 분류 행 전체 펼침, 버튼 실행 opacity 전환과 동작 줄이기를 확인했다. NB01–NB14의 실제 기능 목록은 제품 설계에 있다. 전체 버튼의 두 OS·배율·모니터·첫 방문 인수는 남아 있으므로 DMV-12 전체 완료로 표시하지 않는다.
- 실제 합성 PostgreSQL 두 DB(각 7개 테이블)를 앱으로 연결·비교·저장했다. DATA-01 불일치와 함께 큰 행·RLS·미지원 JSON의 테이블별 확인 불가를 표시했다. SCHEMA-01은 일부 컬럼 속성만 관측하므로 전체 일치를 판정하지 않는다. 연구 RP-D01/RP-C01/RP-S01을 검사 ID·판정·세부 화면에 연결했다.
- 접근성 점검에서 기본 Avalonia PasswordChar 입력의 값 provider가 원문을 노출하는 것을 발견했다. 전용 PasswordTextBox로 마스킹된 provider와 자식 차단을 구현하고 실제 접근성 조회에서 양쪽 암호가 마스킹되는 것을 확인했다. 사용한 것은 격리 fixture의 일회용 합성 암호이며 실제 사용자 접속 정보는 사용하지 않았다.
- JSON은 값·실제 키·접속 정보 없이 범위·판정·이유·안전한 위치·내부 번호를 보관한다. 파일 형식·모델·checksum을 검사하고 임시 작성→다시 읽기 검증→교체한다. checksum은 우발적 손상 검출이며 작성자 인증이 아니다. 앱에서 잘못된 JSON을 열면 복구 가능한 오류를 표시했다. DB 컨테이너 제거 후에도 정상 파일의 같은 run ID·7개 선택 테이블·판정/이유가 복원됐고, 최종 앱의 재저장·다시 읽기 검증 완료 안내를 확인했다.
- 임시 값 조각은 Unix owner-only와 run별 메모리 키의 AES-GCM, 순서·길이·건수·완료 표식 검사, 정상 종료/취소 정리를 갖춘다. 무결성·완전성 문제가 있으면 일치하지 않는다. Windows ACL이 준비되지 않아 Windows 값 경로는 판정을 차단한다.
- 최종 공통/실제 PostgreSQL 테스트 **37개 통과, 실패 0, 건너뜀 0**. 숫자 마지막 자리·NULL/문자 차이·중복/순서·같은 건수 차이·가시성·RLS·미지원/큰 셀·0컬럼 테이블·취소 차이 보존·임시 조각 변조/절단/추가/교체/삭제·권한/정리·보고서 손상·실제 잘못된 CA/호스트 거부·읽기 snapshot/TLS·검사 전후 데이터/정의 무변경을 확인했다. 상세 목록은 [검증 기록](../evidence/native-01/review.json)에 있다. 실제 fixture에서 확인한 타입은 int4/text/numeric이며 다른 구현 codec의 실제 DB 증거를 과장하지 않는다.
- 최종 재현 점검에서 단일 RID publish가 lock 파일을 바꾸는 NU1004를 발견했다. 두 RuntimeIdentifiers를 공통 고정하고 lock 파일을 재생성했다. 잠금 복원→macOS arm64 publish→Windows x64 publish→잠금 복원→전체 37 테스트가 다시 성공했다. 두 OS publish는 경고/오류 없이 완료됐다. macOS는 실제 실행, Windows는 교차 빌드만 확인했다.
- 일회용 컨테이너·자체 TLS 이미지·인증서/암호 임시 폴더를 정리했다. 원본·대상 사용자 DB는 사용하거나 변경하지 않았다. 소스·문서·증거는 로컬 변경이며 commit/push하지 않았다.

## 남은 제품 전체 작업·다음 구현

1. DBMS별 구조·제약·인덱스·사용자·권한·의존 객체를 확장해 미검증을 실제 검사로 바꾼다. SQL Server 전체 값 codec·실제 서버 검증, MySQL/MariaDB도 필요하다.
2. 현재 행당 1 MiB 관측 한계를 대형 LOB 스트림으로 확장하고 메타데이터·결과·임시 경로의 전체 자원 예산, 공간 부족/강제 종료/경로 공격, Windows ACL·잔여 정리를 검증한다. 지금은 초과하면 판정하지 않는다. 무제한 DB 크기 호환을 완료했다고 주장하지 않는다.
3. 수동 대응·LiveCharts2·CSV/HTML·이력·선택 OS 비밀 저장소, 별도 시험 DB 동작과 정리를 구현한다. 선택 카드·검색/일괄 선택·페이지 UI 교정은 이후 [UI-ALIGN-01](ui-alignment.md)에서 완료했으며 이 첫 실행판의 37개 테스트 이력과 이후 38개 회귀를 구분한다. 첫 실행판에는 쓰기 경로가 없다.
4. 두 OS 실제 실행·모든 버튼/애니메이션 인수·사용자 긴 사용 평가·첫 방문 동료의 실제 익명 감상, 릴리스 ZIP·새 임시 폴더 실행·포트폴리오 연결·BR-B 제출이 남아 있다.
