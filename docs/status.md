## 다음 작업

아래 순서로 진행한다. 상세 규칙·설계·인수 기준은 각 정본에 작성하고 이 문서에는 작업 상태를 둔다. 3번 화면 초안에 이어 4번의 첫 실행판을 구현했다. 웹 시안과 실제 앱의 macOS UI 교정을 마쳤고, 다음은 4번의 상세 검사·지원 범위를 확장한다. 2번의 지원 목표·기술 기본값과 화면 시안은 설계안이며 구현·실제 시험에서 확인한다.

1. **논문 검증기 분석 — 정적 분석 완료** — 제출 v19, 19과제 정지 상태 검사 경로, 사후 검토를 대조했다. 코드 23개의 동결판·심사자료 사본 일치를 확인하고 보존 판정·최종 사후 probe 기록을 직접 집계했다. 연구 결과 → 검사 → 판정 → 화면 → 확인 증거의 대응표와 이식 경계를 작성했다. 새로운 DB 재실행이나 제품 성능 검증을 한 것은 아니다.
2. **검사 명세·지원 목표 — 초안 완료** — DBMS별 접속 어댑터·인증/TLS, 읽기 경계·관측 제한, 세부 검사 목록·자료형·키 없음/중복·외부 정렬·임시 보호·시험 DB·판정/중단 모델을 작성했다. 기존 요구 ID 아래 상세 Given/When/Then·반례·증거를 연결했다. 목표 환경을 실제 지원 완료로 선언하지 않는다.
3. **화면 설계 — 초안과 HTML 시안 작성, 검토 가능** — 사용자 동의로 PlandoSee 제약을 해제하고 후속 제안인 Discord 다크 테마를 반영했다. 데스크톱 전용 기준을 RULE·brief·설계에 저장하고 모바일 전환 코드를 제거했다. 연결 → 사전 확인 → 검사 선택·대응 → 실행 전 확인 → 진행 → 결과 → 저장·다시 열기와 선택 시험 준비를 시안에 구현했다. 첫 화면의 논문 제목·도움 문장·세 행동, 버튼/선택 요소 B01–B26/N01–N03, 잘못된 입력·일부 조회·중단·미시작·파일 오류 상태를 구체화했다. 브라우저 예시 흐름은 아래 증거로 구분해 기록하며 실제 Avalonia 화면·사용자 승인·첫 방문 동료 평가가 완료됐다고 기록하지 않는다. 통계 차트의 LiveCharts2 적용 계획은 제품 설계에 보존했다.
4. **앱 구현 — 진행 중, 첫 실행판 완료** — C#·Avalonia 공통 엔진·PostgreSQL 일부 실제 비교·미검증/중단·JSON 저장/재열기가 연결됐다. [구현 기록](native-implementation.md)의 나머지 DBMS·세부 검사를 확장한다. 한국어·영어, 선택 동작 시험, 로컬 이력, CSV·HTML, 보안 저장소 선택, 전체 재검사를 포함한다.
5. **검증과 실제 사용 평가** — 논문 사례·합성 DB로 불일치와 원본 결함, 조회 제한, 잘못된 입력, 중단, 임시 파일 손상·저장 실패, 시험 자료 정리 실패를 확인한다. 각 지원 DBMS·OS에서 무변경과 자원 사용을 확인한다. 앱이 준비되면 사용자에게 긴 실제 사용 검증 작업을 요청한다. 처음 보는 동료의 익명 감상은 실제 수행 후 받는다.
6. **배포와 포트폴리오 연결** — OS·CPU별 실행 ZIP과 README를 만들고 새 임시 폴더에서 실행한다. GitHub 공개 범위·서명 방식을 정해 저장소와 릴리스에 반영한다. 실제 검사와 구분한 예시 UI·결과 소개를 준비하고 12번 사이트 대표작에 논문·앱·도움 문장을 연결한다. 제출 URL이 있으면 새 시크릿 창에서 인증 없이 열리는지 확인한다.
7. **BR-B 제출** — 공개 URL 또는 비밀번호 없는 실행 ZIP, 세 행동과 기대 결과가 포함된 확인 방법, 실제 익명 감상, AI 담당·사용자 직접 판단·따르지 않은 제안과 이유를 준비한다. BRB-C01–C15·C22를 실제 증거로 최종 점검한다.

제품 정책·문서 맥락 구조와 1번 정적 분석은 완료됐다. 2번 검사 명세·3번 화면 초안·4번 첫 실제 앱 증거가 있다. 4번 전체 기능, 두 OS 화면 전체 인수와 5–7단계는 남아 있다.

## 화면 시안 증거

- [시안 안내](../examples/ui-prototype/README.md)대로 `index.html`을 직접 브라우저로 열 수 있다. 설치·계정·DB가 필요 없으며 주소·테이블·계정·결과는 예시다. BR-B 최종 실행 앱이나 공개 URL 통과 증거로 쓰지 않는다.
- 기본 예시 결과는 일치 45·불일치 3·미검증 2다. 분류별 수치 행은 같은 0 기준 검사 건수 축의 작은 막대와 직접 표시한 숫자를 사용하고 미검증을 포함한다. 별도 시험의 기대 충족/불충족·정리 실패와 읽기 비교는 분리했다. HTML 차트는 LiveCharts2 실행 증거가 아니다.
- 격리된 Chrome 브라우저에서 기존 흐름·F01–F08의 138개 데스크톱 시안 점검을 통과했고, 후속 시작 화면 균형 수정은 별도 17개 점검을 통과했다. 후속 수정 뒤 기존 전체 묶음을 다시 실행한 것은 아니다. 새 임시 폴더에 HTML만 복사한 직접 열기도 확인했다. 예시 연결·입력 오류·대응 충돌·선택/확인 차단·취소·미검증 유지·파일 생성/재열기·한영 전환·데스크톱 창·키보드·동작 줄이기를 점검했다. DBMS 카드 방향키, checkbox Space·일부 선택, 검색의 숨은 선택 보존, 검색 결과에만 적용되는 일괄 선택, 대응 검색·충돌 비활성·취소/적용도 확인했다. 기본 문구·입력 경계·초점·판정색의 9개 대비 조합을 계산해 기록했다. 외부 데이터 요청이나 브라우저 오류는 관측되지 않았다. 최종 점검 목록은 [시안 점검 기록](../examples/ui-prototype/evidence/review.json)에 남겼다.

## 미확정

- [설계](product-design.md)의 목표 환경에 대한 실제 DBMS·인증/TLS·OS 지원 증거. 현재 로컬은 macOS arm64이며 로컬 캐시에 SDK 10.0.401을 설치했다. Windows는 x64 교차 빌드만 확인했고 실사용 환경은 미확정이다.
- SDK·패키지 버전과 두 대상 OS lock 파일은 고정했다. 대형 LOB·전체 자원/임시 보호 반례·Windows ACL·나머지 DBMS의 실제 지원 증거는 남아 있다.
- 포트폴리오의 정확한 대표작 위치, GitHub 공개 범위·릴리스 패키지와 서명 방식.
- 실제 DB 행을 찾는 별도 도구는 제안 단계다. 원본값·키 비노출 조건을 사용자 변경 없이 완화하지 않는다.

## 최신 답변

시험 DB 사용자 준비·앱 안내, 기본 시험안 자동 생성 후 확인, 원본 결함 별도 표시, 같은 이름의 계정·역할 비교, 테이블·컬럼·종류·내부 식별번호만 표시, 읽기 기본 선택·동작 기본 해제, 중단 후 전체 재검사만은 확정됐다. 실제 보유 환경은 macOS M4 Pro이며 Windows·DBMS 버전은 미확정이다. 임시 저장 보호와 OS별 실행 묶음 배포는 사용자 동의로 확정됐다. 시험 데이터 정리 정책도 확정됐으며 상세 규칙은 RULE.md가 정본이다. 실제 마이그레이션 사례는 없고 논문 사례 기반 검사를 원한다. 일반 사용자 전체 범위 충족은 검증된 주장으로 기록하지 않는다. 나중에 실제 사용 평가 단계에서 사용자에게 긴 검증 작업을 요청하기로 했다.

## 재도입하지 않을 범위

마이그레이션 실행·운영 O01–O07 시험·기록용 서버/계정 가입·원본/대상 시험 쓰기·전체 데이터 자동 복제는 현재 범위 밖이다. 사용자 요구 변경 없이 다시 추가하지 않는다.
