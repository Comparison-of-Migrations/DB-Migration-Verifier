# UI 구현 1차 체크포인트 · 2026-10-09

## 포함 범위

원본 웹의 9페이지를 C#·Avalonia 실행 앱의 `--replica-preview` 경로로 복제했다. 컴포넌트·페이지 상태와 LOCK은 [COMPONENT_STATUS](replica/COMPONENT_STATUS.md), 원본 조사·상태·상호작용 근거는 [명세](replica/specs/), 완료 당시 검증은 [최종 증거](replica/source/root-final-assembly-proof.json)가 정본이다. 한국어/영어, 실제 macOS/Windows 사용자 흐름과 파일 저장·재열기 증거를 보존한다.

현재 새 화면은 예시 DB와 결과를 사용한다. 기존 기본 실행 경로에는 실제 DB 검사 엔진이 일부 연결되어 있다. **복제 UI와 실제 DB 검사 엔진의 통합은 다음 단계**이며, 이번 체크포인트를 전체 제품 또는 BR-B 제출 완료로 해석하지 않는다.

첫 커밋에는 제품 소스·고정 패키지·테스트·원본 시안·작업 규칙·명세·검증 기록과 기존 엔진 기반을 함께 포함한다. 실행 바이너리·SDK·VM은 Git에 넣지 않는다. 로컬 컴퓨터 전체 파일 목록과 OS 설치/제어 화면 일부는 로컬에만 보존한다. 과거 검증 경로 중 `artifacts/`는 대부분 재생성 자료이므로 제외하되 최종 합성 증거가 직접 인용한 작은 JSON 증거 6개는 포함한다. 정식 릴리스는 아직 없다.

## 이번 푸시 전 확인

- macOS arm64 앱 패키지 복구·실제 첫 화면 실행 확인: [복구 기록](replica/app-launch-recovery-20261009.md).
- 71 LOCK 명세의 보호 파일/범위 변경 없음. 새 디자인·UI 변경은 하지 않았다.
- 엔진 회귀에서 수집기가 없는 사용자·권한/객체 검사를 실행한 것으로 표시하는 문제를 발견했다. 선택 범위의 양쪽 catalog에 해당 검사 section이 전혀 없으면 해당 검사는 미시작/미검증으로 유지한다. 한쪽에라도 section이 있으면 기존 비교·관측 제한 보고를 계속한다.
- 수정 후 테스트: 통과 139, 실패 0, 실제 PostgreSQL fixture 미설정으로 건너뜀 17. 이 건너뜀을 실제 DB 검증 통과로 계산하지 않는다.
- 완료 당시 전체 제품 해시 증거는 당시 버전의 기록이다. 위 Core 교정으로 현재 전체 제품 버전은 달라졌지만 UI 보호 해시는 그대로다. 신규 macOS arm64 Release 빌드 경고 0/오류 0을 확인했다. Windows VM은 삭제 상태라 이번 푸시에서 Windows 실제 검증을 재실행하지 않는다.
- 원본·LOCK·검증 기록의 바이트 해시를 보존하도록 `.gitattributes`에서 자동 줄끝 변환을 하지 않는다. 과거 Windows 측정 JSON의 CRLF와 원본 whitespace는 증거의 일부라 일괄 포맷하지 않는다.
- 게시할 텍스트에서 개인 키·알려진 토큰 형식·비밀번호를 포함한 DB URL 패턴을 검사했다. 검출 없음은 모든 종류의 비밀값이 없다는 완전한 보증으로 주장하지 않는다.

## 남은 작업 · 수행 순서

1. **새 UI에 실제 검사 엔진 연결.** 원본 배치·상태·상호작용과 LOCK을 유지하면서 실제 접속, 조회 가능 범위, 선택/대응, 실행 snapshot, 진행/중단, 결과 상세, 저장·재열기를 연결한다. 예시 흐름은 실제 검사와 구분한다. 수치·연구 ID·미검증 이유가 동일한 결과 모델에서 나오도록 한다.
2. **논문 검사 범위 완성.** PostgreSQL의 원본 제약 위반(DATA-02), 사용자·역할·소유자·권한·RLS 및 view/function/trigger/sequence/사용자 타입의 실제 수집·비교를 완성한다. 현재 일부 registry/Core 초안은 실제 관측 완료가 아니다. DB/서버 전체 발견 범위와 관측 실패를 명확히 한다. 정의 비교와 실제 동작 보장을 구분한다.
3. **DBMS·자료형 지원 확장.** MS SQL은 접속·일부 metadata 기반에서 전체 값/구조 비교로 확장한다. MySQL/MariaDB 어댑터를 구현한다. 각 DBMS의 실제 버전·권한·TLS·자료형 지원 matrix를 증거로 채운다.
4. **대용량·임시 저장 보호 완성.** 현재 1MiB 행 한계, 대형 LOB 스트림, 메타데이터/결과 메모리 예산, Windows ACL 및 경로 바꿔치기·공간 부족·강제 종료 잔여 정리·손상 반례를 해결한다. 문제가 있으면 일치를 판정하지 않는다. 전체 재검사만 제공한다.
5. **별도 시험 DB 동작 시험.** 실제 원본·대상과 분리된 사용자 준비 공간에서 값/기대 결과 확인, 입력·수정·삭제, 앱 소유 자료 정리와 남은 변경 보고를 구현한다. 원본·대상에는 시험 쓰기를 하지 않는다. 백엔드 업무/운영 시험은 범위 밖이다.
6. **로컬 관리 기능.** 설정·이력 파일과 비밀번호 선택 저장용 OS 보안 저장소를 연결한다. 비밀번호 기본 미저장과 화면/로그/보고서 원값 비노출 정책을 유지한다. 계정 로그인·기록용 서버 DB는 추가하지 않는다.
7. **통합 사용성·실제 지원 검증.** 새로운 실제 데이터 흐름의 오류·끊김·중단·긴 이름·대규모 결과·한국어/영어·키보드·창 크기·양 OS를 확인한다. 기존 동일 조건 UI 증거는 재사용하고 새 동작/변경 영향에 집중한다. LiveCharts2는 미적용이며, 적용할 경우 원본 수치/레이아웃/상태를 바꾸지 않는 별도 변경 근거와 검증이 필요하다.
8. **배포·BR-B 제출.** Windows apphost 시작 원인을 해결하고 OS/CPU별 실행 묶음과 README를 만든다. 새 임시 폴더에서 실행하고, 필요한 실제 사용자 평가와 처음 보는 동료의 익명 감상을 받는다. 12번 포트폴리오 대표작에 논문·앱을 연결하고 BRB-C01–C15·C22, 세 행동 확인 방법·AI와 사용자의 판단 세 줄을 실제 증거로 마무리한다.

작업 규칙은 [MASTER_RULES](replica/MASTER_RULES.md), 제품 정책은 [RULE](../RULE.md)를 따른다. 이 목록은 기존 작업을 처음부터 다시 분석하거나 LOCK된 UI를 재설계하라는 지시가 아니다.
