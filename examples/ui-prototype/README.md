# 화면 설계 시안

`index.html`을 브라우저로 열면 된다. 설치·로그인·DB·API 키가 필요 없고 외부 서버에 요청하지 않는다. Windows/macOS 데스크톱 Avalonia 화면을 검토하는 시안이며 실제 C# 앱이나 BR-B 최종 실행 묶음이 아니다. 주소·계정·테이블·결과는 예시이며 DB 쿼리·쓰기·임시 값 저장을 실행하지 않는다. 비밀번호 입력은 비활성이다.

## 세 행동 확인

1. **두 DB 연결과 조회 범위 확인** — 첫 화면의 논문 제목·도움 문장을 읽고 `새 검사 시작` → 기본 예시 그대로 `두 연결 확인` → `조회 범위 확인`을 누른다. 양쪽 연결 확인과 권한 분류의 일부 조회 제한이 보이면 시안 흐름 통과다.
2. **검사 범위 선택과 비교 실행** — `검사 범위 선택`에서 기본 읽기 분류·세 테이블을 확인하고 세부 검사도 펼친다. `실행 전 확인`에서 쓰기를 멈춘 상태를 확인하고 `비교 시작`을 누른다. 분류별 진행이 표시되고 약 7초 뒤 결과 보기로 이동할 수 있으면 시안 흐름 통과다. 이 시간은 실제 DB 성능 수치가 아니다.
3. **차이·미검증 확인과 저장** — `결과 보기`에서 기본 예시의 불일치 3·미검증 2·일치 45, 권한 행의 전체 8 중 미검증 2와 안전한 상세 위치를 확인한다. `결과 저장` → 형식 선택 → `선택 형식 저장`으로 JSON·CSV·HTML 다운로드를 요청한다. 브라우저가 실제 저장한 JSON은 `검사 결과 파일로 보기`로 다시 열 수 있다. 범위·집계가 같고 실제 값·키·비밀값이 없으면 시안 확인 통과다.

빠르게 결과를 보려면 첫 화면의 `예시 결과 보기`를 사용한다. `English/한국어`는 같은 화면과 결과를 다른 언어로 보여준다.

## 잘못된 입력·중단·선택 시험

- 연결 화면에 포트 `0` 또는 `abc`를 넣거나 원본과 대상을 같은 예시 주소·DB로 맞춘다. 안내를 보고 수정할 수 있어야 한다. 실제 연결 오류 검증은 하지 않는다.
- 분류와 테이블을 모두 해제하면 다음 행동이 비활성이고 이유가 보인다. 테이블 대응의 중복 대상도 안내와 함께 거부한다.
- DBMS는 네 선택 카드와 방향키로 고른다. 테이블 검색은 숨은 선택을 바꾸지 않으며 `검색 결과 전체 선택`과 `선택 해제`는 현재 검색 결과에만 적용한다. 일부 선택 상태는 checkbox의 가로선으로 표시한다. 대응 drawer에서는 대상 이름을 검색하고 이미 다른 원본과 연결된 대상의 비활성 이유를 볼 수 있다. 선택은 `대응 적용`을 눌러야 확정되며 취소하면 유지된다.
- 진행 중 `검사 취소`를 누르면 완료·중단·미시작이 구분된다. 판정을 확정하지 못한 항목은 미검증으로 남고 이어하기 대신 `전체 재검사`가 제공된다.
- 동작 시험을 선택하면 별도 시험 DB 준비와 값·기대 결과 확인 흐름이 나타난다. 예시에서는 다른 주소·DB만 입력받으며 실제 DB 분리의 증거가 아니다. 원본·대상에 쓰지 않는다. 시험 완료 예시는 기대 충족/불충족과 정리 실패를 따로 보여준다.
- 잘못된 JSON을 `검사 결과 파일로 보기`로 선택하면 안전한 오류 안내를 표시한다. 이 시안의 예시 파일 형식만 지원하며 향후 앱 파일 호환을 약속하지 않는다.

## 디자인 증거와 남은 검증

`evidence/`에는 첫 화면·DBMS 카드·검사/테이블 선택·대응 drawer·중단·한국어/영어 결과·데스크톱 창 크기별 예시 캡처가 있다. 검토 범위와 최신 자동 점검 결과는 [현재 상태](../../docs/status.md), 버튼별 기능·상태·애니메이션 설계는 [제품 설계](../../docs/product-design.md)가 정본이다.

사용자의 제안을 반영한 Discord 다크 테마 참고 시안이다. 탐색·작업·입력 면을 서로 다른 짙은 회색으로 구분하고 핵심 행동·선택은 Blurple로 강조한다. 핵심 행동은 하단의 큰 강조 버튼, 보조 행동은 해당 정보 옆의 작은 강조 버튼, 중단은 별도 경고 문구로 구별한다. 키보드 초점·누름·비활성·처리 중 피드백과 화면/펼침/dialog/저장 안내 전환이 있다. checkbox/radio는 선택 상태를 애니메이션으로 전달하고 페이지 전체를 재등장시키지 않는다. 동작 줄이기에서는 이동·회전을 줄이고 상태 문구를 유지한다.

차트는 HTML로 그린 설계용 예시다. 실제 Avalonia 구현에는 LiveCharts2를 우선 검토하며, 수치·막대·상세가 동일한 안전한 결과 집계를 쓰도록 계획했다. 두 OS의 실제 Avalonia 동작, DB 비교·보안·파일 저장, 처음 방문한 사용자의 1분 이해 여부는 아직 검증하지 않았다.

플랫폼은 Windows/macOS 데스크톱 전용이다. 모바일 레이아웃은 제공하지 않는다. 브라우저 시안도 최소 960×720 크기를 기준으로 보며, 창이 작으면 브라우저 안에서 스크롤해야 한다. 실제 Avalonia 앱의 최소 창 크기와 OS 배율·모니터 전환은 구현 후 검증한다.

## 화면 피드백 확인

첫 화면은 새 검사·결과 파일 열기·예시 보기의 높이와 기준선을 한 줄에 맞췄다. 새 검사는 채움, 파일 열기는 외곽선, 예시는 낮은 강조로 구분한다. 첫 화면의 **검사 결과 파일로 보기**는 이 시안에서 저장한 JSON을 새 검사 없이 연다. 잘못된 파일은 결과를 덮어쓰지 않고 안전한 안내를 표시한다. 사전 확인의 안내 아이콘·상태·권한 버튼은 상하 중앙에 맞췄다. 검사 분류 헤더는 약 64px이며 헤더를 눌러 세부 검사를 펼친다. 체크박스는 선택만 바꾸고 Enter/Space로 펼침·선택을 각각 조작할 수 있다.

별도 DB 동작 시험을 선택해 시험 준비·기대 결과를 확인하고 돌아오면 준비 수정 버튼 **우측에 예시 DBMS·서버·DB 이름**이 보인다. 수정하면 준비 완료가 무효화되고 재확인 전에는 정보가 표시되지 않는다. 결과는 불일치·미검증·일치 숫자와 같은 0 기준 축의 작은 막대를 함께 표시하며 분류 행 전체가 세부 보기다. 결과 보기·파일 재열기 시 숫자/막대가 짧게 전환하고 필터 변경은 차트 진입을 반복하지 않는다. 동작 줄이기에서는 정적 최종값이 유지된다. 이 화면은 실제 Avalonia·DB 검증이 아니다.

시각화 이론·레퍼런스의 적용 근거와 LiveCharts2 계획은 [제품 설계](../../docs/product-design.md)의 통계 시각화 절에 있다. 요청 항목별 확인 상태와 증거는 [현재 상태](../../docs/status.md), 점검 결과는 [review.json](evidence/review.json)을 따른다.
